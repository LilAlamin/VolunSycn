> **Purpose:** Master project specification for AI coding assistants (e.g., Antigravity AI) to scaffold, build, and maintain **VolunSync** (*System Management for Volunteer Event*) using **Laravel React Starter Kit** and **Dens-UI**.

## 2. Locked Technology Stack

Use a **single modern monolith** architecture—do **not** build a separate REST API backend or mix Livewire/Blade admin panels into the frontend.

| Layer | Technology | Role & Notes |
| :--- | :--- | :--- |
| **Backend Framework** | Laravel (PHP 8.x), Eloquent ORM, Laravel Migrations | Core MVC controllers, validation (`FormRequest`), policies, and relational schema management. |
| **Frontend Bridge** | [Inertia.js](https://inertiajs.com/docs/v3/getting-started) via [Laravel React Starter Kit](https://laravel.com/framework/docs/starter-kits) | Connects Laravel controllers directly to React pages as typed props without building a separate REST API. |
| **Frontend UI** | React 19, TypeScript, Tailwind CSS v4, [shadcn/ui](https://ui.shadcn.com/docs/installation/laravel) | Strict TypeScript components with server-driven Inertia routing and forms. |
| **Design System** | [Dens-UI](https://dendense.github.io/dens-ui/#/docs/installation) (v0.2.0, MIT) | Primary UI component registry (built on `shadcn/ui`, Radix UI, `lucide-react`, Figtree & JetBrains Mono variable fonts). |
| **Admin Data Tables** | [TanStack Table](https://tanstack.com/table/latest) + Dens-UI `Table` | Sorting, division/status filtering, pagination, and row actions inside the Organizer & Coordinator admin dashboards. |
| **Auth & RBAC** | Laravel Starter Kit Auth + `spatie/laravel-permission` | Session-based auth with strict role isolation (`organizer`, `coordinator`, `volunteer`). |
| **Database** | MySQL or PostgreSQL | Relational DBMS enforcing foreign keys and shift-overlap constraints (lock one in `.env`). |
| **QR & Geolocation** | `simplesoftwareio/simple-qrcode`, `html5-qrcode`, HTML5 Geolocation API | Dynamic event/shift QR generation on backend; browser camera scanning + GPS proximity validation on frontend. |
| **Storage & Async Mail** | Laravel Storage, Laravel Mail & Queues (SMTP / Resend) | Role-protected document repository and asynchronous notification pipeline (Priority 2). |

## 3. Project Initialization & Dens-UI Setup

Follow these exact setup steps when bootstrapping the repository:

1. **Scaffold Laravel with React Starter Kit**
   Create the project using the official [Laravel React Starter Kit](https://laravel.com/framework/docs/starter-kits) (which pre-configures Inertia, React 19, TypeScript, Tailwind CSS v4, and `shadcn/ui`).
2. **Install Backend Packages**
   ```bash
   composer require spatie/laravel-permission simplesoftwareio/simple-qrcode
   ```
3. **Install Dens-UI Theme**
   Add the [Dens-UI](https://dendense.github.io/dens-ui/#/docs/installation) theme via the `shadcn` CLI:
   ```bash
   npx shadcn@latest add https://dendense.github.io/dens-ui/r/theme.json
   ```
   Update the global stylesheet (e.g., `resources/css/app.css`) right after Tailwind v4:
   ```css
   @import "tailwindcss";
   @import "@fontsource-variable/figtree";
   @import "@fontsource-variable/jetbrains-mono";
   @import "./styles/dens-ui.css";
   ```
   > **Important:** Remove any default `:root` and `.dark` CSS variables generated by `shadcn init` so they do not conflict with `dens-ui.css`.
4. **Install Dens-UI Components & Frontend Utilities**
   Install required components (or use `all.json` to pull the entire registry):
   ```bash
   npx shadcn@latest add https://dendense.github.io/dens-ui/r/all.json
   npm install @tanstack/react-table html5-qrcode
   ```
   Dark mode in Dens-UI is class-based (`<html class="dark">`).

## 4. User Roles, Registration & Access Control (RBAC)

Enforce authorization via Laravel Policies and `spatie/laravel-permission` middleware on every route.

### Registration & Account Provisioning Rules

* **Public `/register` supports ONLY 2 account types:**
  1. **Volunteer (`volunteer`):** Standard registration (`name`, `email`, `password`). Immediately redirected to `/events` or `/volunteer/applications`.
  2. **Organizer / Community Organization (`organizer`):** Includes `organization_name` (required) and `organization_description` (optional). Stored directly on `users` to support multiple community organizations cleanly while keeping the 7-table ERD intact. Every Organizer is strictly scoped to manage only their own events (`events.organizer_id = auth()->id()`).
* **NO public self-registration for Coordinators (`coordinator`):**
  * Coordinators are provisioned exclusively by an **Organizer** inside `/admin/coordinators`.
  * Organizers can either **create a new Coordinator account** (name, email, temporary password, bound to `created_by_organizer_id`) or **assign an existing user** to `divisions.coordinator_id` and grant them the `coordinator` role.

### Role Matrix

| Role | Access Area | Core Capabilities |
| :--- | :--- | :--- |
| **`organizer`** | `/admin/*` (scoped to own events) | Manage organization profile, full CRUD on own Events & Divisions, create/assign Division Coordinators (`/admin/coordinators`), review/approve/reject all applications for own events, manage all shifts, generate check-in QR codes, view all attendance logs, and (Priority 2) manage documents & analytics. |
| **`coordinator`** | `/admin/*` (scoped to assigned division) | Screen applications for their assigned division, manage division workspace & member directory, schedule/update division shifts, verify QR check-ins, and (Priority 2) upload division meeting minutes. |
| **`volunteer`** | `/volunteer/*` | Manage personal profile, browse active events/divisions across organizations, submit division applications, track real-time selection timeline, access assigned division workspace & shift calendar, scan QR + submit geolocation check-in, and view verified service hours. |

## 5. Relational Database Schema (7 Core Tables)

All migrations must enforce foreign keys, cascading rules, and indexes while preserving the 7-table ERD from the STACK 2026 proposal.

| Table | Key Columns & Relationships | Constraints & Business Rules |
| :--- | :--- | :--- |
| **`users`** | `id`, `name`, `email`, `password`, `phone`, `avatar_url`, `bio`, `organization_name` (nullable), `organization_description` (nullable), `created_by_organizer_id` (nullable FK `users`), `timestamps` | Roles managed via `spatie/laravel-permission`. `organization_name` is required when registering as `organizer`; `created_by_organizer_id` links organizer-provisioned `coordinator` accounts to their parent organization. |
| **`events`** | `id`, `organizer_id` (FK `users`), `title`, `slug`, `description`, `venue_name`, `venue_lat`, `venue_lng`, `checkin_radius_meters`, `start_date`, `end_date`, `status` (`draft`, `open`, `ongoing`, `completed`) | Coordinates + radius are used for HTML5 Geolocation check-in validation. Scoped per organizer (`organizer_id`). |
| **`divisions`** | `id`, `event_id` (FK `events`), `coordinator_id` (nullable FK `users`), `name`, `description`, `quota`, `timestamps` | Represents functional teams (e.g., Logistics, Media, On-Site Operations). |
| **`applications`** | `id`, `user_id` (FK `users`), `event_id` (FK `events`), `division_id` (FK `divisions`), `motivation`, `status` (`submitted`, `under_review`, `accepted`, `rejected`), `reviewed_by` (nullable FK `users`), `reviewed_at`, `reviewer_notes`, `timestamps` | Unique constraint on `(user_id, event_id, division_id)`. Moving status to `accepted` automatically grants access to the division workspace. |
| **`shifts`** | `id`, `event_id` (FK `events`), `division_id` (FK `divisions`), `title`, `description`, `start_time`, `end_time`, `location`, `qr_token` (unique), `timestamps` | Plus pivot table `shift_user` (`shift_id`, `user_id`, `assigned_at`) to assign volunteers to shifts. **Overlap Validation Rule:** Before assigning a volunteer to a shift, reject if they already have an assigned shift where `existing.start_time < new.end_time AND existing.end_time > new.start_time` (0% double-booking). |
| **`attendance_logs`** | `id`, `shift_id` (FK `shifts`), `user_id` (FK `users`), `checked_in_at`, `checked_out_at`, `checkin_lat`, `checkin_lng`, `verification_method` (`qr`, `geolocation`, `qr_and_geo`), `verified_hours` (decimal), `status` (`checked_in`, `completed`, `flagged`), `timestamps` | Unique `(shift_id, user_id)`. On check-out (or shift completion), auto-compute `verified_hours` from timestamps. |
| **`documents`** | `id`, `event_id` (FK `events`), `division_id` (nullable FK `divisions`), `uploaded_by` (FK `users`), `title`, `file_path`, `mime_type`, `file_size`, `visibility` (`event_all`, `division_only`, `organizers_only`), `timestamps` | Migration included early for schema integrity; full upload/download UI is reserved for Priority 2. |

## 6. Feature Scope & Implementation Phases

Respect the strict competition boundary between **Priority 1 (MVP — build now)** and **Priority 2 (Final Day Build Session on 16 December 2026)**.

### Priority 1 — MVP (Build Now for Semifinal)

1. **Identity, Multi-Organization Onboarding & Volunteer Application**
   * Two-role registration (`Volunteer` vs `Organizer / Organization`) and login using Dens-UI `Login` block, `Tabs`, and form components.
   * Organizer-managed Coordinator provisioning (`/admin/coordinators`) to create Coordinator accounts or assign existing users to divisions.
   * Public/authenticated Event & Division explorer (`Card`, `Badge`, `Tabs`) displaying organization name and quota availability.
   * Division application form with motivation/preferences submission.
2. **Administrative Screening & Live Status Timeline**
   * Organizer/Coordinator screening dashboard powered by [TanStack Table](https://tanstack.com/table/latest) + Dens-UI `Table`, `Select` (filter by event/division/status), `Badge`, and `Dialog` (review details + approve/reject with notes).
   * Volunteer-facing **Live Status Timeline** (`Progress`, `Card`, `Badge`, `Alert`) reflecting real-time stage progression (`Submitted` → `Under Review` → `Accepted` / `Rejected`).
3. **Automated Division Workspace & Shift Scheduling**
   * Approving an application automatically places the volunteer into their division workspace showing coordinator contact info, peer directory (`Avatar`, `Card`), and division announcements.
   * Shared shift schedule view and Coordinator shift assignment interface with **strict server-side overlap validation** preventing double-booking.
4. **QR Check-In & Automated Hour Logging**
   * Organizer/Coordinator generates and displays a unique shift QR code (`simplesoftwareio/simple-qrcode`).
   * Mobile-friendly volunteer check-in page using `html5-qrcode` camera scanner + HTML5 Geolocation API (Haversine distance check against `events.venue_lat/lng` and `checkin_radius_meters`), with graceful local caching/retry notice for low venue connectivity.
   * Automatic calculation and display of verified volunteer service hours in both volunteer profile and admin attendance logs.

### Priority 2 — Reserved for Final Day (16 December 2026)

> **AI Agent Instruction:** Keep database migrations and clean navigation placeholders ready, but do **not** implement the full Priority 2 modules unless explicitly instructed during the Final Day session.

1. **Integrated Document Archiving Repository:** Role-protected file upload/download via Laravel Storage for meeting minutes and official correspondence.
2. **Automated Email Queue & Multi-Channel Alerts:** Background queue workers via Laravel Mail & Queues for acceptance emails and shift reminders.
3. **Organizer Analytics Dashboard:** Summary visual dashboard using Dens-UI `Chart` components for division capacity fulfillment, turnout rates, and total verified hours.

## 8. Synthetic Seeder & Quality Guidelines for AI Development

* **Realistic Test Seeder (`DatabaseSeeder`):** Include a dedicated seeder generating **2–3 sample community organizations** (e.g., SIPA Surakarta & local community initiatives), organizer-assigned division coordinators, **100+ simulated volunteer profiles**, **5 mock community events**, multiple divisions per event, sample applications across all statuses, and multi-division shift schedules so the team can benchmark screening workflows and record the 2-minute demo video cleanly.
* **Validation & Error Handling:** Put all validation in Laravel `FormRequest` classes; display inline validation errors in React using Inertia's `useForm` hook.
* **Shift Overlap Guard:** Encapsulate shift conflict detection in a dedicated service class (e.g., `App\Services\ShiftConflictService`) with unit/feature tests proving 0% double-booking.
* **Geolocation Guard:** Implement Haversine distance calculation in `App\Services\AttendanceVerificationService` so check-in radius validation is enforced server-side (never trust client-side distance checks alone).
* **UI Consistency:** Always prefer components from `@/components/ui/*` installed via the [Dens-UI](https://dendense.github.io/dens-ui/#/docs/installation) registry rather than writing ad-hoc custom CSS.
